# モデルと 3DGS・写真の差分を確認する

数字を出す前に、まず目で見ます。確認の方法は 4 つあり、見えるずれの種類が違うので組み合わせて使います。

| 方法 | 見えるもの | 道具 |
|---|---|---|
| A. 写真の視点での 4 列比較 | 形の欠け・余分・位置のずれ・向き（表と裏）・見え方 | `views.py select/lfs` → `bl_views.py` → `compare_sheet.py` |
| B. ユーザーの LFS 視点の再現 | ユーザーが気にしている場所そのもの | `views.py viewport` → 同上 |
| C. 点群との 3D 距離 | 系統的なずれ（厚み・オフセット）、作り忘れ、根拠の無い形 | `export_points.py` → `bl_point_diff.py` |
| D. 個別の点の三角測量 | 細い物・点群に無い物の位置、寸法（スケール） | `views.py find` → `pick3d.py` |

## A. 4 列比較（写真｜3DGS｜Blender｜重ね）
```
python views.py P.json select <set> --near x,y,z --n 6 [--maxdist 40]    # その点が写っている写真を、向きを散らして選ぶ
python views.py P.json lfs <set>                                          # 同じ学習カメラで 3DGS をレンダリング
(Blender) VIEWCFG={"set": "<set>", "mode": "render", "width": 640}; exec bl_views.py
python compare_sheet.py P.json <set>                                      # views\<set>_sheet.png と _scores.json
```
- 写真と 3DGS は画素単位で一致します。3DGS が崩れている所（フローター・ぼけ）は、写真の方を信じます。3DGS も写真も同じ物を示しているのにモデルだけ違えば、それがモデルのずれです。
- 重ね列は、写真を暗くし、モデルの輪郭（シルエットと折れ線）を赤で描いたものです。赤線が写真の物の縁から外れていれば、位置か寸法のずれです。
- "edge match" は、モデルの輪郭が写真の強い縁の近く（既定 4 px）にある割合です。テクスチャや影も縁になるので、絶対値には意味がありません。**同じ視点で修正前後を比べる**ための数字です。
- 背景が透明（＝そこに形が無い）なのに写真に物があれば、作り忘れです。逆に、写真に何も無い所にモデルの面があれば余分です。
- **画面一面が灰色**なら、カメラがモデルの中（柱や壁の中）にあります。そこには実際には物が無いので、モデルの位置が間違っています。
- 物の両側を見ます。`--near` は方位 45° ごとに散らして選びます。向き（標識や窓の表）は、表が見える写真がどの方向から撮ったものかで決まります。
- 撮影リグのビュー名（front/left/…）は、手持ちの 360° カメラでは向きが一定ではありません。左右の判断は座標で行います。

## B. ユーザーの LFS 視点
ユーザーが LFS で視点を見せて「ここが違う」と言ったら、まずその視点を再現します。
```
python views.py P.json viewport            # camera_get + その画面のキャプチャ → views\lfs_view.json
(Blender) VIEWCFG={"set": "lfs_view", "mode": "render"} ; exec bl_views.py
python compare_sheet.py P.json lfs_view    # 1 列目と 2 列目は同じ LFS キャプチャになる
```
`mode: "create"` にすると、Blender に同じカメラを作ります。ユーザーが Blender 側でその視点から覗けます。

## C. 点群との 3D 距離（bl_point_diff.py）
```
python export_points.py P.json sfm --box=x0,y0,z0,x1,y1,z1         # 負の値を含む box は --box=... の形で渡す
(Blender) PDIFF={"points": "points_sfm.npy", "collections": ["Building"], "tol": 0.15, "max_dist": 2.0}; exec bl_point_diff.py
```
- **点 → モデル**: 各点から最も近い面までの距離を測ります。`fit` は tol 以内の割合です。物ごとの `mean_signed`（法線方向の符号付き中央値）が大きく偏っていれば、その物は系統的にずれています（例: +0.4 m ＝点が面の 0.4 m 手前 → 壁を 0.4 m 外へ出す、または厚くする）。
- **作っていない物**: `max_dist` より遠い点を 1 m の格子で集めた塊が `unmodelled_clusters` です。点の多い塊から写真で正体を確かめます（車・人・植栽など、作らなくてよい物も多い）。
- **モデル → 点**: 面の上に一様に点を取り、近くに点群があるかを見ます（`supported`）。低いと、データに根拠の無い形です。ただし、滑らかな・暗い・ガラスの面は SfM の点にならないので、低いからといってすぐ消さず、写真で確かめます。3DGS の点（`export_points.py 3dgs`）なら、もっと密です。
- 色付きの点（緑＝合っている、黄＝近い、赤＝作っていない）を、`Diff` コレクションに表示します。比較レンダリング（`bl_views.py`）は既定で `Diff` を隠します。
- tol の目安: SfM の点のばらつきは、撮影距離 10 m で数 cm〜数十 cm です。まず 0.15〜0.3 m で全体を見て、物ごとの偏りを追います。
- 3DGS の平らな面（路面・床・壁）は、大きく平たいガウシアンで表されます。既定の `--max-scale 0.3` では消えて、地面の `supported` がほぼ 0 になります（実例）。面の支持を見るときは `--max-scale 1.5` 程度に上げます。
- 3DGS の点は、フローターを `--min-opacity` / `--max-scale` で落としても残ります。モデルの外に赤が散らばるのは普通です。塊になっている所だけを見ます。

## D. 個別の点（pick3d.py）
- 細い柱・電線・ガラス・縁のように点群に現れにくい物は、写真上の画素から位置を出します。`views.py find x,y,z --out sheet.png` で、その付近が写っている写真を切り出し、画素を読みます。
- 2 枚以上の写真で同じラベルを選ぶと三角測量になります。光線のずれ（ray miss）が小さく、光線の角度が 5° 以上離れていることを確認します。
- 1 枚だけなら、z = h の水平面との交点を求めます（柱の根元なら h = 0）。
- 既知の寸法の両端を選ぶと、距離が出ます。スケールの検証と修正に使います（`setup_project.py <dir> --rescale`）。

## E. 仕上げの差分比較（写真と同じ視点の最終レンダー）
A〜D は形の確認で、Workbench の単色や 3DGS と比べます。E は**最終の材質と光のまま、写真と同じ姿勢・画角・解像度で描いて並べ**、見た目の差を 1 つずつ原因まで掘って直す往復です。実例（高架の現場、360° カメラの cubemap 11 面）で、歩道の段差、余分な建物と樹木、舗装の範囲、桁下の設備の位置、明るさの差が、2 回の往復で直りました。

### 準備
1. 確認したい物を 8〜12 か所決め、`targets.json` にモデル座標と見たい距離の範囲を書く（標識・橋脚・縁石と側溝・桁下・交差点・遠景の建物など）。
2. `cmp_select.py` の候補一覧を見て、物ごとに 1 枚選ぶ。点数は「中央に写る・距離がちょうどよい・ぶれていない」だけなので、手前の車や柱で隠れていないかは目で見る。標識を正面から写した面は点数で上がりにくいので、標識の前を通るフレームの各面に標識を投影して（`Project.project_model`）探す。cubemap の `_top` 面は桁下・天井、`_bottom` は使わない。
3. `cmp_set.py` で写真を**加工せずに**複製し、`cameras.json`（姿勢・fx/fy/cx/cy・解像度）を書く。
4. `bl_cmp_render.py` で描く。アニメーションの車両や煙などのコレクションは `hide` で外す。1920×1920・128 spp で 1 枚 10 秒前後なので、1 回の MCP 呼び出しは 4 枚まで（超えると呼び出しは時間切れになるが Blender は描き続ける。描き直す前にファイルの時刻を見る）。

### 読み方（順番）
1. **輪郭の重ね**（`cmp_review.py sheets` の 3 列目）で形を見る。赤線が写真の縁から外れていれば位置・寸法、写真に何も無い所の赤線は余分な物、赤線の無い写真の物は作り忘れ。
2. 違う所を**原寸で切り出し**（`crop`、100 px の目盛り付き）、写真の画素を読む。
3. その画素を `bl_cmp_probe.py` に渡し、**モデルの何が写っているか**を確かめる。思っていた物と違うことが多い（実例: 歩道の段差は、歩道の裏まで伸びていた車道の帯に縁石が付いたもの。木の茂みは鉄塔の緑の金網。白い壁は撮影範囲の外に置いた倉庫）。
4. 正しい位置は写真から測る。写真の画素を地面（その場所の高さ）と交わらせる（`Project.pixel_ray_model` を地面の高さで反復）か、2 枚で三角測量する（`pick3d.py`）。近い所の点を採り、地面すれすれに見える遠い所の点は信じない。点群の地図（真上の色・密度）の「抜け」を形と読まない。実例では、点群の抜けを塀の切り欠きと読んで作ったが、写真では塀はまっすぐだった。
5. 色と明るさは、同じ枠の平均色（`patch`）で数字にして合わせる。日なたの路面、開けた日陰、高架の下面、橋脚の側面、空、を最低 1 か所ずつ測る。

### 直し方
- 直すのは生成スクリプトとパラメーター（規則）。同じ規則で作った他の場所にも効く。Blender 上での手直しはしない（再生成で消える）。
- 直す前に `cmp_review.py keep` で今の版を `_v1` に残し、直した後に全視点を描き直して**修正前後の並び**（`_before_after_XX.jpg`）を見る。光や材質の変更は全視点に効くので、1 か所のために他を悪くしていないかを確かめる。
- 差分は表（場所・写真・モデル・原因・直し方）にしてユーザーに見せ、直す順番を合わせる。

### 光の合わせ方（実例の数字）
360° カメラの写真は、開けた日陰は物理的に正しい暗さ（路面の日陰が日なたの約 45%）なのに、高架の下面や橋脚の側面は日なたの路面と同じくらい明るく写る（地面の照り返しとカメラ側の階調処理）。一律の環境光では「日陰が明るすぎる」と「桁下が暗すぎる」が同時に起きる。
- 環境光（空）は、カメラ以外の光線に対して方向別に強さを変える: 上空から弱く（0.55 倍）、地平線付近から強く（4 倍）。
- 地面の材質（路面・歩道・縁石・芝など）は、拡散反射の光線から見たときだけ明るくする（Light Path の Is Diffuse Ray で基本色を 5 倍）。カメラから見た地面の色は変えずに、桁下と橋脚の側面だけが明るくなる。
- 結果（写真／モデル、0–255）: 桁下 89／90、橋脚の側面 105／103、開けた日陰の歩道 50／53〜57、日なたの歩道 118／121。
- コンポジターで局所的に明るさを持ち上げる方法も試したが、日陰の歩道まで明るくなって合わなかった。

## 確認の進め方
1. 大きな形から確認します（地面・主要な構造・建物の箱）。細部は、大きな形が合ってから見ます。
2. 区間・部位ごとに A を 4〜6 視点で行います。直したら同じ視点で再確認します（edge match と目視）。
3. C で、系統的なずれと作り忘れを洗い出します。
4. 最後に、ユーザーの LFS 視点（B）と、全体を見渡す視点で画像を作り、ユーザーに送ります。
5. 材質と光まで入ったら、E の差分比較を回します。写真と並べた比較フォルダ（写真・レンダー・`cameras.json`・一覧画像）は、ユーザーが自分で見比べる資料にもなります。

# Blender のモデルを Three.js（ブラウザ）で見せる

Blender で作ったシーンを、ブラウザで歩き回れる・フライスルーできる 1 ページにするときの汎用の手順と、踏んだ失敗。UE への移行（[unreal.md](unreal.md)）と同じ材質の式を使い回せる。シーンに固有の設定（材質の種類ごとの作り込み、季節ごとの色・太陽・曲など）はレシピに書く（実例: `recipes/temple_gate/RECIPE.md` の「Three.js 版」= 屋外の境内と季節の切り替え、`recipes/wooden_school/RECIPE.md` の「Three.js 版」= 室内に入れる建物と、現況 / 復元の切り替え。後者は `threejs/` にページ一式がある）。

## 構成
| 置き場所 | 中身 |
|---|---|
| `web/public/` | 公開する一式だけ: `index.html`、`proc.js`（材質のシェーダー）、`materials.json`、`scene.json`（太陽・カメラ軌跡）、`static.glb`、`veg.glb`、`veg.json`（インスタンス行列）、BGM。別案（現況と復元など）があるときは、建物・木・配置を別案ごとのファイルにする |
| `web/backup/`・`web/logs/` | 以前の版、書き出しログ（公開しない） |
| `web/export_web.py` | 背景 Blender で `public/` に書き出す |
| `web/serve.ps1`・`README.md` | 手元のサーバー、公開手順 |
| `scripts/threejs/shader_check.html`（このスキルの道具） | 材質を 1 つずつ描いて、シェーダーのコンパイルで落ちる材質を探す。材質のモジュールに `shaderCheckList()`（`[[名前, () => マテリアル], ...]` を返す）を書き、公開フォルダにコピーして開く |

公開フォルダと作業ファイルは最初から分ける（途中で混ざり、実例で分けるよう指摘された）。ブラウザは `file://` から glb / json を読めないので、手元では `python -m http.server --bind 127.0.0.1 --directory public`。スマホ実機で試すには LAN 公開（`--bind 0.0.0.0`）かサーバーへのアップロードが要る。**ユーザーが自分でアップロードする場合、直したら「どのファイルを上げ直すか」を毎回伝える**（古い版がサーバーに残っていて、直したはずの症状のスクリーンショットが届いた）。

## 書き出し（Blender → glb）
- 建物・地形は 1 つの `static.glb`（Draco 圧縮、マテリアル名を残す）、木の原型と葉のカードは `veg.glb`、配置は `veg.json`（原型ごとの 3×4 行列の並び）にして、ブラウザ側で `InstancedMesh` にする。
- **書き出した物の名前を、ビューアが実際に見つけているかを数える**。複製したオブジェクトに Blender が付ける `.001` を GLTFLoader がさらに `TW_x001` に変えるため、`vegNodes["TW_x"]` が 1 つも当たらず、**最初の版からずっと幹と下草が 1 本も描かれていなかった**（実例での指摘で発覚）。名前は末尾の `.?\d{3}` を落とした基底名でも引けるようにし、読み込み後に「原型ごとのインスタンス数」をコンソールに出して確かめる。
- **インスタンスの行列は `matrix_world` ではなく `matrix_basis`（位置・回転・拡大）から取る**。ビューポートで非表示にしてあるオブジェクト（遠景の森など、レンダーにだけ出す物）は、背景実行の Blender では `matrix_world` が評価されず単位行列のままになる。実例では森の木 728 本が全部「原点に高さ 1 m」で書き出され、建物の角に桜の混じった茂みができ、山には森が無かった（実例での指摘で発覚）。**本数だけでなく、層ごとの位置の範囲と高さの範囲を書き出しのログとビューアのコンソールに出し**、「全部が 1 か所にある」ときは書き出しを止める。
- **面の向き**: Blender は両面を描くので裏返りに気づけない。ビューアが片面描画だと、裏向きの面（階段の踏面など）は**上から見ると消えて中が見える**。全部の静的な材質を `side: DoubleSide`（`shadowSide` も）にするのが確実。
- **幹のメッシュ**: 枝の骨格を「節ごとに別の筒」で作ると、曲がる所の外側に楔形の隙間が開く。節の継ぎ目で輪を共有する連続した管にする（二等分面で切り、枠はねじれないように運ぶ）。原型のメッシュだけ差し替えれば、配置や葉は作り直さなくて済む。
- **粗くした地形は、石段や舗装の面を突き抜ける**（上に地面の模様が載る）。読み込み時に、段・舗装の下にある地形の頂点を面の下へ押し下げる。**頂点ごとのレイキャストは数十秒かかる**: 段・舗装の三角形を 12.5 cm 格子の高さ表にラスタライズして引くと 0.2 秒で同じ結果になる。
- **視点を変えて確かめる**: フライスルーの視点だけで確認していると、真上からの見え方（踏面の欠け、地形の突き抜け）を見落とす。自由視点で上・横・近接からも見る。

## 材質: 画像を使わず、式で画素ごとに描く
- 頂点カラーへの焼き込みだけでは、目地・粒・木目が出ない。**UE 用に書いた HLSL の材質ライブラリを GLSL ES 3 に移す**と、同じ見た目が画素単位で出る（`MeshStandardMaterial.onBeforeCompile` で `color_fragment` と `normal_fragment_maps` を差し替え、凹凸は高さ関数の 3 点勾配から法線を作る。材質ごとの数値は `materials.json`）。座標はモデルのメートル（three.js のワールド (x, y, z) → モデル (x, −z, y)）。
- **全部の種類を 1 本のシェーダーに入れると、ブラウザ（ANGLE / D3D）のコンパイルが数分固まる**。種類ごとに `#if PKIND == n`（`material.defines`、`customProgramCacheKey` も種類ごと）で分け、1 つのプログラムにはその種類の式だけを入れる。
- 凹凸の高さ関数は 1 画素で 3 回評価されるので軽く書く（ボロノイを入れない、オクターブを減らす）。凹凸はカメラから一定距離までにして、共有の uniform（画質設定で 0 にできる）で切る。
- 質感は「高さ関数（凹凸と、窪みを暗くする陰り）＋風化（汚れ・苔・雨だれ・色むら）＋部材 1 枚ごとの色調」の組で作る。**垂直面にも目地や筋が出るよう、面の向きで UV を作り分ける**（水平面は平面座標、垂直面は「面に沿った水平距離と高さ」）。上向きの判定（雪・苔）は、頂点法線が傾いている部材では面法線（`cross(dFdx, dFdy)`）で行う。材質の種類ごとの具体的な要素はレシピに書く。
- 画素ごとの粗さは、色の関数でグローバル変数に倍率を入れ、`roughnessmap_fragment` の後で掛ける（塗装の褪せた所だけつやを落とす、など）。
- 地形は焼いた頂点カラーを「配置（土・落ち葉・砂利）」として使い、細かい模様だけ式で足す（頂点属性を別に書き出さなくて済む）。
- **材質を全部式で描くなら、書き出しで色を焼かなくてよい**（Cycles のベイクが要らず、書き出しが数分で済む）: 建物はマテリアル名だけを残して 1 メッシュにまとめ（マテリアルごとに 1 プリミティブ = 描画命令 1 回）、UV も書き出さない。頂点カラーは「式に渡す値」に使う（地形の被覆、草の葉の根元からの高さなど）。葉のカードの色は、葉のマテリアルの 2 色の間で乱数で決める。
- 板の目地・タイルの継ぎ目のような細い線は、`fwidth` で 1 画素ぶんぼかし、遠くでは平均の明るさに寄せる（そのままだと遠景でちらつき、屋根瓦はモアレになる）。

### Windows のブラウザ（ANGLE / D3D）で落ちる書き方
WebGL のシェーダーは Windows では HLSL に変換されて D3D のコンパイラにかかる。GLSL として正しくても、次の書き方はコンパイラの内部エラー（`X8000 ... Negate modifier not allowed for operand`、`Error compiling dynamic pixel executable`）になり、**最初の描画で WebGL のコンテキストが失われる**。
- **符号を反転したシェーダー入力を、条件式（`? :`）で直接選ぶ**。座標変換で `p = vec3(w.x, -w.z, w.y)` としておき、`mode < 2.5 ? p.x : p.y` と書くと落ちた。軸は定数ベクトルを条件で選び、`dot(p, k)` で取り出す。
- **定数配列（`const vec3 A[4] = vec3[4](...)`）をループで添字参照する**のは避け、uniform の配列にする（全マテリアルで同じ uniform オブジェクトを共有すればよい）。
- **ループの中で、条件によって読むテクスチャを変える**（`cond ? texture(a, uv) : texture(b, uv)`）のも避け、両方を `textureLod` で読んで `mix` する。
- 落ちたときの調べ方: **材質を 1 つずつ小さな箱に貼って順に描き、1 つ描くたびに `readPixels` で強制的にコンパイルさせ、`renderer.info.programs` の `diagnostics.programLog` を記録する確認ページ**で調べる（`scripts/threejs/shader_check.html`。最後に名前が出た材質、またはログのある材質が原因。実例では板張りの種類だけにログが出た）。**シェーダーを書いたら、本体のページを開く前にこの確認ページを通す**（本体で落ちると、その origin の WebGL が止まる）。本体のページでは数十の材質が一度にコンパイルされ、どれが原因か分からない。
- **コンテキストを 2 回失うと、ブラウザはその接続元（origin）の WebGL を止める**（`Web page caused context loss and was blocked`。再読み込みでは戻らない）。確認を続けるには別の origin で開く（`http://名前.localhost:ポート/` はどれも手元のサーバーに届き、名前ごとに別の origin になる）。

## 植生
- 葉は原型ごとのカード（ボクセルごとに 1 枚、面積で大きさ、葉の平均色）。枚数は近景 5,000・遠景 900 程度まで増やして初めて「葉の塊」に見えなくなる。カードの UV は 2×2 のアトラスの 1 区画をランダムに選び、絵柄（葉脈のある小枝）はキャンバスに描く。
- **カードは、ボクセルの面積重心ではなく「そのボクセルの中の葉 1 枚（面積で重みを付けて乱数で選ぶ）」の位置に置く**。葉が密な樹冠では面積重心がボクセルの格子に並び、横から見ると樹冠が横縞に見えた（遠景用の粗いカードで特に目立つ。実例での指摘）。格子の原点も原型ごとに乱数でずらし、カードの大きさも少しばらつかせる。ボクセルの番号は 1 つの整数にまとめて `np.unique` にかける（3 列のまま `axis=0` でかけると 70 万枚の葉で 1 原型 1 分かかり、まとめると全原型で 20 秒になった）。
- **幹と枝は近くで見て確かめる**（歩く視点で幹の横に立つ）。節ごとの筒のままだと切れ込みが見える（上の「幹のメッシュ」）。原型 1 本の骨格を作る関数を生成スクリプトの中で独立させておくと、書き出しのときに幹だけ今の関数で作り直せる（.blend を作り直さなくて済み、葉は同じ乱数の同じ骨格なので合う）。
- 樹皮は縦の筋のある式（樹種で色と筋の細かさを変える）。インスタンスでもワールド座標で描ける（`instanceMatrix` を掛けた位置を varying に入れる）。
- LOD はチャンク単位（45 m 格子）で近景・遠景のカードを切り替える。

## ライティング
- リアルタイムの間接光は無いので、**画面空間の環境遮蔽（SSAO）を自前で入れる**: シーンを深度テクスチャ付きの HDR ターゲットに描き、全画面パスで深度だけから遮蔽を計算してトーンマップする。**深度だけを使う方式なら、アルファテストの葉やインスタンスに専用のマテリアルが要らない**（法線を別パスで描く方式は、葉のカードが四角い板として遮蔽に出る）。float ターゲットに描けない端末向けに 8 bit へ落とす分岐を入れる。
- 太陽は方位角・高度から置く（モデルの +Y が真北から何度ずれているかは、撮影時刻の太陽の向きから逆算できる）。空の色に合わせて半球ライトの上下の色を変えると照り返しらしくなる。

## 季節・音・言語などの切り替え
- 見た目の別案（季節・天候・時刻など）は、共有の uniform（案の番号と雪などの量）を全マテリアルで参照し、葉は「木の種類ごとのマテリアル」に色替え・非表示・積雪の uniform を持たせる。空中を舞う物（花びら・雪・落ち葉）は、カメラに付いてくる箱の中を折り返す `InstancedMesh`。案ごとの数値は 1 つの表にまとめる。
- **舞う物は「見えるか」を先に確かめる**: 実寸に近い花びら（4 cm）は 20 m 先で 1 画素を切り、控えめな数だと「散っていない」と言われた（実例での指摘）。遠い粒は最低でも 1.6 画素ぶんの大きさで描く（カメラからの距離に比例して拡大、上限は元の約 3 倍）。**地面に落ちた粒（動かない `InstancedMesh`。木の下に濃く、離れると薄く）を足すと、少ない数でも「散っている」と伝わる**。地面の粒は地形の高さを格子の双一次補間で求めて 1.5 cm 浮かせ、`polygonOffset` を付ける。量を増やすときも、落ちる速さと横風は変えない（速さの好みは別に決まっていることが多い）。
- **「風に流される」は、全部の粒が同じ風を共有して初めてそう見える**: 風速を時刻だけの関数（一定の風 ＋ ゆっくりした強弱）にし、粒が落ち始めてからの風の積分を式で求めて横に動かす（粒ごとにばらばらの揺れは、風ではなく乱れに見える）。落ちた粒は、同じ計算の着地点（樹冠の真下から風下いっぱいまで）に置くと、空中と地面がそろう。**降らせる範囲は発生源（その木）の周りに限り、発生源の無い所に漂わせる粒を足さない**（校庭全体に花びらを置いたら「桜の木の周辺だけに」と指摘された）。着地点や途中が屋根の下になる粒は作らない。
- BGM は numpy で合成してループにする。**ループ長＋余韻の尾を 1 ファイルにし、次の周回をループ長ちょうどで重ねて再生する**と、AAC の前後の無音に関係なく継ぎ目が出ない（WebAudio の `AudioBufferSourceNode` を時刻指定で予約）。音はユーザーの操作の後にしか鳴らせないので、ボタンで開始する。**音量のスライダーを最初から付け、既定は控えめにする**（実例: 固定の音量で出して「下げられるように」と言われた。スライダーの値は 2 乗して使うと小さい音量を合わせやすい。選んだ値はブラウザに保存）。
- **別案ごとに曲を分けるなら、「同じ曲の 2 つの状態」として同じ長さ・同じ拍・相性のよい和音（長調と平行短調など）で作る**。2 曲を同時に走らせて音量だけを変えれば、切り替えは同じ小節の中のクロスフェードになり、左右比較では境界の位置で混ぜられる（別々の曲だと、切り替えのたびに頭から鳴り直すか、混ぜると濁る）。等パワー（sin / cos）で混ぜ、`setTargetAtTime` で 0.3 秒かけて追従させる。
- 合成した曲は聴いて確かめられないので、**旋律だけ・伴奏だけを別々に描いて音量差を測る**（旋律が伴奏より 2〜3 dB 上。実例では持続音の伴奏が旋律を 2 dB 上回っていた）。帯域ごとの割合・最大値・左右の相関も出す。報告には「聴いていない」と書く。scipy が無い環境では、フィルターと畳み込みを FFT で書けば numpy だけで足りる（Blender 同梱の Python で動く）。
- 言語はブラウザの優先言語で初期化し、ボタンでも切り替えられるようにする（優先順位: URL の `?lang=`、ボタンで選んだ保存値、ブラウザの言語）。HTML に書いた文言を元の言語として覚えておけば、再読み込み無しで往復できる。

## 別案を画面の上で切り替える・並べる（現状と復元、施工前後など）
- 別案ごとに glb を分け（建物・地形と、木の原型・配置）、ブラウザでは別案ごとの `Group` にする。カメラ軌道・太陽・建物の平面などの共通の情報は 1 つの json にまとめる。
- **描くときは「表示する別案だけ `visible` にしてシーンを描く」を別案ごとの描画先（深度テクスチャ付き）に対して行い、全画面パスで画素ごとにどちらを出すかを決める**。境界の位置を動かせば、ワイプでの切り替えにも、左右に並べる比較（境界をドラッグ）にもなる。片方しか画面に出ない間は片方だけ描く。影は描画ごとに計算し直されるので、別案ごとに正しい影になる。
- 別案ごとの天気（太陽の強さ・空・霧・環境光のテクスチャ）は、描く直前に切り替える。環境光のテクスチャ（PMREM）は起動時に別案の数だけ作っておく。
- 1 コマに何度も `render` するときは `renderer.info.autoReset = false` にして、コマの頭で `reset()` する（そのままだと三角形の数が最後の全画面パスの 2 枚になる）。
- 起動時に全部の別案を 1 回ずつ描いてシェーダーをコンパイルしておく（切り替えた瞬間に固まるのを防ぐ）。

## 室内（部屋に入れるモデル）
- ブラウザには間接光が無く、空の光（半球ライト・環境マップ）は屋根があっても部屋の中まで届いてしまう。**建物の平面（矩形）と天井の高さを uniform で渡し、その内側では空の光を減らす**（外壁からの奥行きで徐々に暗く、屋根の穴の下は明るく）。天井より上は、下向きの面（屋根の裏）だけを室内として扱う（屋根の上面まで暗くしない）。太陽の直射は影の計算で窓や穴から入る。
- 室内の環境光は暖色に寄せる（空の青い光のままだと、床と漆喰が青灰色になった）。カメラが室内に入ったら露出を上げる（建物の平面の内側かどうかで判定し、数秒かけて変える）。
- **ガラスは影を落とさない設定にする**（落とすと窓から日が入らない）。半透明・両面・深度は書かない。
- 「歩く」見方は、床の矩形と高さの表（パラメータから書き出す）と、地形の頂点を格子にまとめた高さ表だけで作れる（床・地面に沿って目の高さを保つ）。壁の当たり判定は無いので、そう明記する。

## 読み込み画面
- データのファイルは `fetch(name, { cache: "no-cache" })` で読む（書き出し直した glb がブラウザのキャッシュから出てきて、直っていないように見えるのを防ぐ。変わっていなければサーバーは 304 を返すだけ）。
- 大きい glb は `fetch` のストリームで受け取り、受信バイト数で ％ を出す（その後 `GLTFLoader.parseAsync` に渡す）。gzip のときは Content-Length が圧縮後の値なので、概算の大きさを控えに持つ。
- **ダウンロード後の「展開」「準備」は測れない**ので、段階名（n / 全体）と、動き続ける印を出す。同期処理でメインスレッドが止まる間も動くのは **transform だけの CSS アニメーション**（コンポジタで動く）。段階の間で `setTimeout` を await して文言を描かせる。
- **起動中に `requestAnimationFrame` を await しない**（裏のタブでは発火せず、読み込みがそこで止まった）。
- シェーダーのコンパイル（`renderer.compileAsync`、待ちすぎないよう上限付き）と最初の 1 コマの描画は、読み込み画面が出ている間に済ませる（消えた直後に固まるのを防ぐ）。

## スマホ
- 画質の段階（軽量・標準・高）を用意する: 画素比、凹凸の距離、SSAO の有無、影の解像度、葉の詳細表示の距離、遠くの植生のカリング距離、粒子の数。既定をどれにするかはユーザーに聞く（端末で自動的に下げるか、常に高で始めるか）。ボタンと `?q=` で切り替えられるようにする。
- 画面: `100dvh`、キャンバスに `touch-action: none`、狭い画面ではパネルを折りたたんで始める。
- 端末エミュレーションで確認できるのは判定とレイアウトまで。**実機の速度とタッチ操作は確認していないと明記する**。

## 確認のしかた
- 変更ごとにブラウザで開き、コンソールのエラー、数か所の視点（地上・近接・真上）、全部の季節を見る。確認用のブラウザ画面が非表示だと `requestAnimationFrame` が止まり、fps も測れない: 速度の数字は「その条件での値」として伝える（他の処理が GPU を使っていると半分以下になる）。
- **フライスルーの視点だけで済ませず、歩く視点で近づいて見る**。実例で指摘されたのは、どれも近づけば分かる物だった: 幹の横（節の切れ込み）、建物の角（原点に固まった木）、各部屋の壁の上端（届いていない柱）、置いた物の向き、遠景の樹冠を望遠で（カードの縞）。確認する場所の一覧を先に作り、報告に「見た所」として書く。
- 確認用のブラウザの画面キャプチャは 1 コマ遅れることがある（視点を変えた直後に撮ると前の視点が写る）。視点を変えてから 1 秒待って撮る。
- 報告には、見た視点・季節と、見ていない物（実機、他の季節、音）を書く。
